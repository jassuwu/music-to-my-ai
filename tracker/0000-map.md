## Destination

A working v1 Chrome extension in this repo — loaded unpacked, personal-toy polish — that sonifies streaming LLM responses on claude.ai and chatgpt.com as generative music. The map is done when the extension is installed and audibly musical on both sites, with nothing left to decide.

## Decisions so far

- [Audio tech for MV3 content scripts](tickets/0001-audio-tech-for-mv3-content-scripts.md) — raw Web Audio API in the content script with a small lookahead scheduler; AudioContext unlocked by a one-time mousedown/keydown `resume()`; no offscreen document (30s idle auto-close, two-hop messaging), no Strudel (pattern-loop mismatch); Tone.js is the sanctioned fallback if hand-rolled voices get costly.
- [Streaming DOM anatomy of claude.ai and chatgpt.com](tickets/0002-streaming-dom-anatomy.md) — claude.ai adapters should hook `data-is-streaming` on the message wrapper plus `data-testid` attributes; chatgpt.com should hook `[data-testid^="conversation-turn-"]` + `data-message-author-role`, ~~with stop-button presence as the streaming signal~~ (**superseded by live measurement — the stop button flickers mid-stream and lingers after the end; see Live DOM verification below**); selectors on both sites break every 2–6 months, so adapters need defensive fallbacks; mutation granularity needs live verification → [Live DOM verification on claude.ai and chatgpt.com](tickets/0006-live-dom-verification.md).
- [Sound-mapping prototype](tickets/0003-sound-mapping-prototype.md) — **Direct wins**: one sound per Chunk, fired on arrival, no smoothing. Every smoothed candidate (quantize, arpeggio drain, ambient pad) read as music playing *alongside* the stream; the naive 1:1 hit is what gives the stream impact. Alternatives discarded rather than kept as packs, so the sound-pack architecture is dropped and [Control surface](tickets/0004-sound-packs-and-control-surface.md) is rescoped. Voice character still open → [Voicing the Direct mapping](tickets/0007-voicing-the-direct-mapping.md).
- [Voicing the Direct mapping](tickets/0007-voicing-the-direct-mapping.md) — **Kalimba is the default voice** (major pentatonic, transpose 0, reverb 0.32, gentle-walk pitch, burst-thinning on); pitch must move between hits. **The Instrument is user-selectable** — a roster of real instruments (piano, guitars, bass, violin, sitar, veena, harmonium, harp) with a pleasant default. This swaps voice only, never the Mapping, so it does not revive Sound Packs. Opens [Instrument library: samples or synthesis](tickets/0008-instrument-library.md); volume-with-pleasant-default goes to Control surface.
- [Instrument library: samples or synthesis](tickets/0008-instrument-library.md) — bundle sparse (~1 note/octave) sample files extracted offline, played by a small hand-rolled sampler (closest note + `playbackRate` shift) on raw Web Audio; no runtime SF2/SFZ parsing and no CDN fetch, because MV3 gates content-script `fetch()` behind the host page's CORS/CSP. Assets ship via `web_accessible_resources` + `chrome.runtime.getURL()`, decoded once at init so switching instruments is instant. **v1 roster (6):** kalimba, piano, acoustic guitar, bass, harp, sitar — all CC0/MIT-equivalent, ~1MB total. Pizzicato violin and electric guitar were extracted and then **cut by ear**; six is also exactly the number of tines the comb picker wants.
- [Live DOM verification on claude.ai and chatgpt.com](tickets/0006-live-dom-verification.md) — measured on both signed-in sites. **No wholesale re-renders on either** (the feared case), so MutationObserver holds. Adapters must watch **`characterData` *and* `childList`** — the split is 174/63 on chatgpt.com but 46/75 on claude.ai. **A Chunk is one observer callback with net growth**, giving 4.8–6.6 notes/sec; per-record firing would be unplayable (claude.ai's median inter-event gap is 1ms). **End-of-stream = ~900ms of no growth**, since claude.ai's `data-is-streaming` true→false is clean but chatgpt.com has no trustworthy flag (stop button flickered mid-stream and lingered after the end). Traps: chatgpt.com renumbers turn `data-testid`s live, and `document.body` attribute observation is drowned by sidebar churn — scope to the conversation container. Surfaced [How an oversized Chunk should sound](tickets/0009-oversized-chunks.md).
- [Extension scaffolding decisions](tickets/0005-extension-scaffolding-decisions.md) — **bun only: no Vite, no WXT, no plugins.** An extension is not a frontend app (no dev server, `manifest.json` is the entry, the content script must be a single IIFE, asset filenames must stay literal for `chrome.runtime.getURL`), and `bun build --target=browser --format=iife --watch` covers exactly the four gaps those frameworks exist to paper over. Vite+ rejected as a repo-toolchain layer that solves none of them. TypeScript, run natively by bun. Layout grouped by role so adding a site or an instrument has an obvious home. Dev loop is `--watch` plus a manual reload. Git initialised, small commits; **commits are unsigned** because the hardware signing key needs a physical touch.
- [Control surface](tickets/0004-sound-packs-and-control-surface.md) — **toolbar popup only, no in-page UI**, plus a `chrome.commands` mute shortcut (the only urgent control is "stop now"). Instrument picker **auditions a 3-note phrase on select**. Volume: one slider defaulting to **~60%**, with per-instrument gain trims baked in. Global on/off plus a per-site toggle, both sites on by default. **Nothing beyond instrument is exposed** — register/reverb/pitch-movement/burst-thinning stay tuned constants. Settings in `chrome.storage.sync`. No-gesture edge case: stay silent, no banner.

- [Sample extraction pipeline and instrument definitions](tickets/0013-sample-pipeline.md) — the whole roster came from **one** source, `gleitz/midi-js-soundfonts`' render of FluidR3_GM (MIT), rather than the four sample projects the research named — including `pizzicato_strings` for the violin. Sparse set of two notes per octave a fifth apart (max ~3 semitones of shift): **72 samples, 1.32 MB**. No ffmpeg step needed — the renders are already per-note mp3s. Gain trims are starting values only; the tuning pass finalises them.

- **Build tickets** — [skeleton](tickets/0010-extension-skeleton.md), [core engine](tickets/0011-core-engine.md), [adapters](tickets/0012-site-adapters.md) and [samples](tickets/0013-sample-pipeline.md) are all closed and verified live on claude.ai. Notable finding: **the oversized-Chunk path barely fires on claude.ai** — a 2,000-word code block arrived as ~295 incremental 28-41 char Chunks, not a bulk flush, so the heavy hit never triggered. The 5,405-char Chunk the probe once saw was a whole-message re-render the adapter now correctly ignores.

## Not yet specified

- **Multi-stream behavior** — two tabs streaming at once, regenerated/branched responses, background-tab audio. Sharpens once the extension is running on real pages; may turn out to need nothing.

## Out of scope

- **Chrome Web Store publication and other browsers** (Firefox/Safari) — charter Q5: personal toy; publication is a possible follow-on effort with its own constraints.
- **Veena and harmonium in the v1 roster** — both were asked for by name, both deferred by [Instrument library](tickets/0008-instrument-library.md): veena has no source whose licence permits bundling raw samples in a redistributed product (the one good pack explicitly forbids it), and harmonium has no safe source *and* its bellows-driven drone is a poor structural fit for one-shot triggering. Revisit only if a licensed source appears; harmonium would additionally need a sustain-aware mapping, which Direct is not.
- **Generic any-site fallback adapter** ("any element rapidly growing text") — v1 is two adapters (charter Q4); the fallback would be a fresh effort after v1.
